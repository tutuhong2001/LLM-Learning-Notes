# 微调与 LoRA

微调使用训练数据更新模型参数，适合调整输出风格、任务行为或特定任务表现。LoRA 冻结原有权重，只训练低秩适配参数，能够减少可训练参数量和优化器状态开销。

RAG 通过外部资料补充知识，微调则改变模型参数。频繁更新的事实知识常先考虑 RAG；稳定的格式或任务行为可以考虑微调。二者并不是互斥方案。

微调需要训练集与独立验证集，还要关注过拟合、数据许可与训练成本。本项目仅讲解微调概念，没有实现 LoRA 训练，不能以本项目宣称完成过微调实验。

# RAG：检索增强生成

RAG（Retrieval-Augmented Generation）先从知识库检索相关资料，再把资料与用户问题一起交给大模型生成回答。它适合企业文档问答、学习笔记搜索以及经常更新的知识。

典型流程是：文档清洗 → 切分 → 向量化 → 检索 top-k → 组装上下文 → 生成带来源的回答。更新外部知识通常只需要重建索引，不需要重新训练模型。

RAG 不能消除幻觉：检索可能遗漏证据，模型也可能错误解读资料。因此应返回来源，在证据不足时拒答，并分别评估检索质量和回答质量。RAG 与微调可以组合使用。

# OpenAI 兼容接口

Python OpenAI SDK 可通过 OpenAI 客户端调用 chat.completions.create，传入 model 和 messages 获取回答。部分服务提供兼容接口，通过 base_url 指定服务地址。

OPENAI_API_KEY 用于认证，OPENAI_MODEL 指定服务商实际支持的模型 ID，OPENAI_BASE_URL 可选。兼容协议不保证支持所有参数，应查阅具体服务商文档。不要把密钥写入源码或提交到 Git。

网络请求应设置超时和有限重试，注意速率限制与调用费用。本项目的 ask 命令会发送问题以及检索到的文档给配置的服务商；--dry-run 只在本地打印请求，不会调用 API。
